# Principios de Diseño

> La interfaz de Narrador Studio no busca impresionar.
> Busca acompañar el proceso creativo.

---

# Filosofía

Narrador Studio es una herramienta para crear.

No es un panel administrativo.
No es un ERP.
No es un CRM.

Cada decisión visual debe ayudar al usuario a concentrarse en escribir, organizar y producir narraciones.

La interfaz debe desaparecer para que el contenido sea el protagonista.

---

# Principio 1
## Una pantalla, un objetivo

Cada pantalla responde una única pregunta.

Ejemplos:

Dashboard

> ¿Qué vamos a crear hoy?

Projects

> ¿En qué proyecto quieres trabajar?

Sections

> ¿Qué parte del guion quieres editar?

Narraciones

> ¿Qué audio quieres generar?

Exportaciones

> ¿Cómo quieres publicar?

Si una pantalla intenta responder demasiadas preguntas, debe dividirse.

---

# Principio 2
## Baja densidad visual

La interfaz debe respirar.

El espacio vacío es parte del diseño.

No llenar una pantalla únicamente porque exista espacio disponible.

Cada nuevo módulo debe mantener una densidad visual igual o menor que el Dashboard.

---

# Principio 3
## El contenido es el protagonista

La tecnología nunca debe competir con el contenido.

Las estadísticas solo existen cuando aportan valor.

No mostrar gráficos, indicadores o métricas decorativas.

El usuario vino a crear narraciones.

No a observar un panel.

---

# Principio 4
## Los estados vacíos enseñan

Un estado vacío nunca representa un error.

Debe indicar claramente cuál es el siguiente paso.

Incorrecto:

No hay datos.

Correcto:

Aún no tienes proyectos.

Crea el primero para comenzar a organizar tus narraciones.

---

# Principio 5
## La simplicidad es una decisión

Agregar una funcionalidad requiere una justificación.

Agregar un componente visual también.

Si una tarjeta, botón o sección no aporta valor inmediato, no debe existir.

---

# Principio 6
## La interfaz evoluciona con el producto

La interfaz nunca debe anticipar funcionalidades inexistentes.

Las áreas futuras pueden mostrarse para explicar el camino del producto, pero nunca deben generar falsas expectativas.

Las funciones aparecen cuando realmente existen.

---

# Principio 7
## Consistencia antes que originalidad

Es preferible repetir un patrón conocido que inventar uno nuevo para cada pantalla.

Los mismos componentes deben comportarse siempre igual.

Los usuarios aprenden patrones, no pantallas.

---

# Principio 8
## Diseño editorial

Narrador Studio se inspira más en una mesa de trabajo editorial que en un software administrativo.

El contenido debe sentirse:

- tranquilo;
- ordenado;
- claro;
- legible;
- humano.

No debe sentirse corporativo ni recargado.

---

# Principio 9
## Accesibilidad desde el inicio

La accesibilidad no es una etapa final.

Forma parte del diseño.

Cada nueva pantalla debe considerar:

- navegación por teclado;
- jerarquía correcta de encabezados;
- contraste suficiente;
- foco visible;
- lenguaje claro.

---

# Principio 10
## El Dashboard es la referencia

El Dashboard define el sistema visual del producto.

Los nuevos módulos deben heredar su estructura, espaciado y lenguaje visual.

No deben convertirse en aplicaciones distintas.

---

# Principio 11
## Menos dependencias, más claridad

Las decisiones de diseño deben apoyarse en herramientas simples.

Bootstrap resuelve la estructura.

El CSS propio aporta identidad.

JavaScript añade comportamiento.

La tecnología nunca define el diseño.

---

# Principio 12
## Diseñado para durar

Narrador Studio es un proyecto de largo plazo.

Cada decisión visual debe seguir teniendo sentido dentro de cinco o diez años.

Se priorizan la claridad y la mantenibilidad sobre las tendencias pasajeras.

---

# Nuestra pregunta

Antes de agregar cualquier elemento a la interfaz, siempre debemos preguntarnos:

> ¿Ayuda realmente al usuario a crear mejores narraciones?

Si la respuesta es no, ese elemento no pertenece a Narrador Studio.

## Manifiesto

La mejor interfaz es aquella que el usuario deja de notar porque está completamente concentrado en crear.
